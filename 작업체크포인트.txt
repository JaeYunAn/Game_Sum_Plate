## 2. 작업 원칙

1. 기존 코드와 구조를 최대한 보존한다.
2. 실제 코드를 확인한 뒤 필요한 부분만 수정한다.
3. 존재하지 않는 코드나 파일을 가정하지 않는다.
4. Codex와 파일 첨부는 사용하지 않는다.
5. Git Bash 명령어 중심으로 작업한다.
6. 여러 파일 수정은 가능한 한 하나의 명령어로 통합한다.
7. Python으로 파일을 수정할 경우 기존 코드와 일치하는지 먼저 검사하고, 다르면 즉시 중단한다.
8. 이미 확인한 코드는 다시 요청하지 않는다.
9. 불필요한 리팩터링이나 기능 추가를 하지 않는다.
10. 한 번에 하나의 작업만 진행한다.
11. 설명은 생략하고 필요한 명령어와 코드만 제공한다.
12. 기존 게임의 작동 방식과 점수 계산을 임의로 변경하지 않는다.
13. 데이터베이스 파일과 기존 기록을 삭제하거나 초기화하지 않는다.
14. 사용자가 별도로 요청하지 않는 한 새로운 라이브러리나 프레임워크를 추가하지 않는다.
15. 기능 구현 시 프론트엔드와 백엔드의 역할을 명확하게 구분한다.

## 3. 진행 방식

다음 순서를 반드시 따른다.

1. 수정 요구사항 분석
2. 관련 코드 수집 명령어 제공
3. 사용자가 실행 결과 전달
4. 실제 코드 분석
5. 수정 명령어 제공
6. 수정 결과 확인
7. 문법 및 기능 검증

작업 진행 규칙:

- 먼저 관련 코드를 수집할 Git Bash 명령어 하나만 제공한다.
- 사용자가 실행 결과를 전달하면 해당 코드를 분석한다.
- 분석이 끝나면 실제 수정 명령어를 제공한다.
- 여러 파일을 수정할 때는 가능한 한 하나의 Python 명령어로 통합한다.
- 수정 명령어는 기존 코드의 일치 여부를 먼저 검사한다.
- 예상과 다른 코드가 발견되면 어떤 파일도 수정하지 않고 중단한다.
- 수정 후에는 문법 검사와 변경 사항 확인 명령어를 제공한다.
- 브라우저에서 직접 확인해야 하는 기능은 브라우저 검증 전까지 완료로 간주하지 않는다.
- 한 번에 여러 단계를 진행하지 않는다. 사용자가 완료 결과를 전달하면 다음 단계로 이동한다.

| 메서드 | 경로 | 기능 |

GET `/api/records`의 duration은 정수형으로 처리한다. 과거 `Literal[30, 60]`의 문자열 쿼리 매개변수 검증 문제를 수정한 상태다.

## 6. 회원 기능 구현 현황

### 회원가입

- 닉네임만 입력받는다.
- 비밀번호는 사용하지 않는다.
- 닉네임 중복 가입을 방지한다.
- 대소문자를 구분하지 않고 중복을 검사한다.
- 회원가입 성공 시 서버에서 무작위 인증 토큰을 발급한다.
- 인증 토큰은 SHA-256 해시로 변환하여 서버에 저장한다.
- 브라우저에는 인증 토큰을 localStorage에 보관한다.

### 회원 상태 유지

- 페이지를 새로고침해도 회원 상태가 유지된다.
- 페이지 최초 실행 시 `/api/me`를 호출하여 회원 상태를 확인한다.
- 인증이 유효하지 않으면 게스트 모드로 전환한다.

### 게스트 모드

- 회원가입 없이 게임을 이용할 수 있다.
- 게임 기록을 조회할 수 있다.
- 게임 기록은 저장할 수 없다.

### 회원 모드

- 시간 제한 모드 이용 가능
- 게임 기록 저장 가능
- 전체 순위 조회 가능
- 기존 기록 조회 가능

### 회원탈퇴

- 회원탈퇴 시 회원 정보가 삭제된다.
- 회원 인증 토큰도 무효화된다.
- 기존 게임 기록은 삭제하지 않는다.
- 기존 기록의 닉네임은 기록에 남긴다.
- 기존 기록은 전체 순위표에서 계속 조회할 수 있다.

## 7. 기록 공유 구조

현재 프로젝트의 가장 중요한 목적은 여러 사용자가 하나의 게임 기록을 공유하는 것이다.

역할을 다음과 같이 분리한다.

### 사용자 PC

각 사용자의 브라우저에서 다음 작업을 수행한다.

- 번호판 문제 생성
- 타이머 작동
- 정답 및 오답 판정
- 점수 계산
- 게임 결과 산출
- 회원 인증
- 서버에 기록 전송
- 서버에서 전체 기록 수신

### 서버 PC

서버는 다음 작업만 수행한다.

- 회원가입 및 회원 관리
- 인증 토큰 검증
- 게임 기록 저장
- 전체 게임 기록 조회
- 순위표 데이터 제공

게임 연산은 서버에서 수행하지 않는다.

서버는 사용자가 전송한 점수를 신뢰하고 저장한다. 클라이언트에서 조작된 점수도 저장될 수 있다는 위험을 감수한다.

목적은 대규모 경쟁 서비스가 아니라 약 20명 규모의 소규모 게임 기록 공유다.

## 8. 데이터 및 기록 관련 주의사항

- 모든 사용자의 기록은 하나의 SQLite 데이터베이스에 저장한다.
- 게스트와 회원 모두 기존 기록을 조회할 수 있다.
- 기록 저장은 회원만 가능하다.
- 회원탈퇴 후에도 기록은 보존한다.
- 기록 조회는 선택한 게임 시간과 난이도를 기준으로 한다.
- 각 조건별 TOP 10을 표시한다.

기존 서버 이전 이전에 브라우저 localStorage에 저장되어 있던 기록은 서버로 자동 이전되지 않았다.

따라서 기존 로컬 기록 이전은 아직 완료되지 않은 작업이다.

사용자가 별도로 요청하지 않는 한 임의로 기존 localStorage 기록을 삭제하거나 이전하지 않는다.

## 9. 외부 접속 구성

현재 외부 접속은 Cloudflare Tunnel을 이용한다.

### cloudflared 설치

winget으로 설치 완료.

패키지:
`Cloudflare.cloudflared`

설치 버전:
`2026.10.7`

실행 경로:

`C:\Program Files (x86)\cloudflared\cloudflared.exe`

Git Bash 실행 명령어:

```bash
"/c/Program Files (x86)/cloudflared/cloudflared.exe" --version
```

### FastAPI 서버 실행

첫 번째 Git Bash 터미널:

```bash
.venv/Scripts/python.exe -m uvicorn server:app --host 127.0.0.1 --port 8000
```

개발 중 자동 재시작이 필요한 경우:

```bash
.venv/Scripts/python.exe -m uvicorn server:app --host 127.0.0.1 --port 8000 --reload
```

### Cloudflare Tunnel 실행

두 번째 Git Bash 터미널:

```bash
"/c/Program Files (x86)/cloudflared/cloudflared.exe" tunnel --url http://127.0.0.1:8000
```

실행 시 다음과 같은 HTTPS 주소가 생성된다.

`https://임의의문자열.trycloudflare.com`

생성된 주소를 다른 사용자에게 전달하면 외부 접속이 가능하다.

### 외부 접속 운영 원칙

- FastAPI 서버와 Cloudflare Tunnel을 모두 실행해야 한다.
- 두 터미널을 종료하지 않는다.
- PC가 종료되거나 인터넷이 끊기면 접속할 수 없다.
- Quick Tunnel 주소는 실행할 때마다 바뀔 수 있다.
- 공유기 포트 포워딩은 사용하지 않는다.
- 서버는 127.0.0.1에서만 실행한다.
- Cloudflare Tunnel은 외부 요청을 로컬 서버로 전달한다.

### 외부 접속 검증 현황

- cloudflared 설치 완료
- 실행 확인 완료
- Quick Tunnel 생성 성공
- Cloudflare 연결 사전 검사 통과
- 외부 접속용 HTTPS 주소 생성 확인

다만 다른 PC에서 실제 접속 및 회원가입, 기록 저장까지 확인한 것은 별도로 검증해야 한다.

현재까지의 회원가입, 기록 저장, 기록 조회 기능은 구현 완료된 상태다.

이전에 완료한 기능을 불필요하게 다시 구현하거나 변경하지 않는다.

새로운 수정 요구사항이 입력되면 반드시 관련 코드부터 수집한다.

기존 구조를 최대한 활용하고, 필요한 부분만 수정한다.

서버와 프론트엔드가 연결된 구조이므로 기능 수정 시 다음을 구분하여 검토한다.

- HTML 화면 구성
- JavaScript 게임 및 API 호출
- CSS 디자인
- FastAPI API 처리
- SQLite 데이터 저장

한 번에 하나의 작업만 진행한다.

첫 응답은 관련 코드를 수집할 Git Bash 명령어 하나만 제공한다.
